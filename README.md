# D&N

Учёт денег, в котором ни один платёж не остаётся без записи.

После каждой оплаты (Apple Pay, перевод, SMS банка, Monobank) операция попадает в очередь
**«Не разнесено»**, и телефон сразу предлагает выбрать, куда ушли деньги. Плюс дерево подразделений,
лимиты карт с цветовой индикацией и прогноз расходов.

## Что уже работает (этап 1, MVP)

- Главная: сумма «не разнесено», расходы месяца по подразделениям с прогнозом, предупреждения по лимитам.
- Очередь «Не разнесено» с подсказкой трёх вероятных подразделений и экраном «Куда ушли деньги?».
- Подразделения: дерево любой глубины, цвет, бюджет, «внутренние переводы» (не считаются расходом).
- Лимиты карт: лимит на каждую карту, зелёный / жёлтый / оранжевый / красный (перелимит), общий итог,
  «с какой карты лучше платить», прогноз дня исчерпания лимита.
- Приём операций: `POST /api/ingest` (Apple Pay и SMS через «Команды» iOS), `POST /api/monobank` (вебхук).
- PWA: ставится на экран «Домой» iPhone.

Техническое задание и план этапов — в документе ТЗ. Настройка iPhone — [docs/IPHONE_SETUP.md](docs/IPHONE_SETUP.md).

## Запуск

Нужен Node.js 22.13+ (используется встроенный `node:sqlite`).

```bash
npm install
cp .env.example .env.local   # вписать DN_APP_PASSWORD и DN_INGEST_TOKEN
npm run dev                  # http://localhost:3000
```

```bash
npm test         # тесты логики (лимиты, разбор сумм и SMS)
npm run build    # сборка
```

Данные хранятся в `data/dn.db` (SQLite). Поэтому для работы в интернете нужен сервер с постоянным диском
(VPS или Railway с volume). Vercel и другие «бессерверные» хостинги не подходят, пока не сделан переход
на PostgreSQL (этап 2, вместе с отдельными пользователями и ролями).

Интерфейс закрыт паролем `DN_APP_PASSWORD`. API приёма операций (`/api/ingest`, `/api/monobank`)
работает только с ключом `DN_INGEST_TOKEN`.
